﻿# AppForge 已知问题与限制（v1.0）

> 原则：**失败必须可见、可修、可回滚，且不污染已有应用。** 下面这些是当前版本明确已知的边界。

---

## 1. 交付形态

| # | 项 | 说明 |
| --- | --- | --- |
| 1 | 单文件首次启动稍慢 | 单文件是"启动器 + 压缩包"，首次运行需把 payload **在内存中解压**到可写目录（约 1 秒），之后复用不再解压 |
| 2 | 单文件不是"免解压单进程" | 解压后的真身仍是普通 exe（在同目录），这是 .NET Framework 下不引第三方打包器的取舍 |
| 3 | **SmartScreen 未签名提示** | 程序未购买代码签名证书，Windows 可能提示"无法识别的应用"。处理：更多信息 → 仍要运行，或 `Unblock-File`。**想避免就优先用绿色便携包** `dist\AppForge-portable.zip` |
| 4 | 受限目录会自动换位置 | 若 `%LOCALAPPDATA%` / `%TEMP%` 被策略或杀软限制，程序自动回退到 exe 同目录并记日志（`logs\launcher.log`），不会直接启动失败 |
| 5 | 便携数据目录 | 默认数据在 `%LOCALAPPDATA%`；如需 U 盘便携，用 `--data-dir=<路径>`（或在 exe 同目录放 `portable.flag`） |
| 6 | 未做自动更新 | 升级 = 换掉 exe / 解压新便携包，数据目录不变即可继承 |

## 2. 兼容性

| # | 项 | 说明 |
| --- | --- | --- |
| 5 | 最低系统 | Windows 10 22H2（19045）+ / Windows 11 x64。低于此版本会明确提示并不启动 |
| 6 | WebView2 依赖 | Win11 自带；Win10 多数随 Edge 预装；缺失时首启自动静默安装（需联网）。企业禁用安装时可用"选择离线安装包"或降级为仅逻辑模式 |
| 7 | 高 DPI | 已适配 PerMonitorV2（200% 缩放下布局正确）；但**高 DPI + 大窗口下 WebView2 内存偏高**（本机 200% 缩放实测：宿主 54MB + WebView2 子进程合计约 390MB）。普通 100% DPI 机器会明显更低，后续版本会缩小默认窗口并复核 |
| 8 | 双机验收 | 单文件版已在开发机（Win11 26200）完整验证；**干净 Win10/Win11 虚拟机的安装/卸载验收仍待执行**（需要真实虚拟机环境） |

## 3. 生成能力边界

| # | 项 | 说明 |
| --- | --- | --- |
| 9 | 目标形态 | v1 聚焦**单页静态应用**（HTML/CSS/JS，离线可跑、`localStorage` 持久化）。不做后端、不做需要构建/多依赖的复杂前端工程 |
| 10 | 规模上限 | 单文件 ≤1200 行 / ≤200KB，总文件 ≤8，生成阶段单文件写入 ≤400KB（超限会拒绝并提示模型收敛） |
| 11 | 模型要求 | 需要支持 `tools`（function calling）的模型；不支持时会给明确报错并建议换 `gpt-4o-mini` |
| 12 | 修复次数 | 自测失败自动修复最多 3 轮；仍失败则给出可读诊断（页面报错、body 长度、`data-app-root` 检测结果），**不产生坏应用** |
| 13 | 并发 | 同一时间只跑 1 个生成/修改任务（避免草稿互相污染），并发请求会返回"已有任务在进行中" |
| 14 | 修改上下文 | 修改模式会注入现有文件全文（单文件 40K、总量 240K 字符，超出截断）；超大应用可能改不全 |
| 15 | 生成期间关窗口 | 会取消任务并清理草稿（自测依赖同进程 WebView2）。这是预期行为，但请注意不要在关键步骤关闭 |

| 16 | 版本对比降级 | 超大文件（LCS 规模 > 约 200 万格）只给整体行数变化，不给逐行预览 |

| 19 | 托盘常驻 | 关闭窗口默认隐藏到托盘（不是退出）；退出请用托盘右键 → 退出 |
| 20 | 搜索 | 支持名称/描述/ID 的子串匹配（含中英文），不做拼音首字母/模糊纠错 |
| 21 | 深色模式 | 跟随系统深浅色；应用内主题由 AI 生成的应用自己决定 |

## 5. 数据与安全

| # | 项 | 说明 |
| --- | --- | --- |
| 22 | 密钥 | DPAPI（CurrentUser）加密，换 Windows 用户/重装系统后需重新填写 |
| 23 | 生成代码的沙箱 | 应用运行在独立 origin，**无宿主 API 通道**、禁外链、禁 `eval` 远程代码；但生成的应用本身仍可能联网（`fetch`），联网行为会提示 |
| 24 | 命令执行 | v1 生成阶段**不允许模型执行任意命令**（只写文本文件），避免误删/下载执行风险；后续如需构建类应用会引入分级确认 |
| 25 | 审计 | 应用与版本操作、生成过程均写日志到 `logs\`；诊断包含日志副本（不含密钥明文） |
| 26 | 回收站保留 | 删除的应用保留 7 天后自动清理（启动时清理超过 7 天的条目） |

## 6. 已知但暂不做的功能

- 多端同步 / 账号体系（纯本地单用户）
- 应用商店 / 一键分享链接（当前用 zip + 快捷方式）
- 应用内二次开发的可视化编辑器（以自然语言 + 代码只读视图为主）
- 脚本类应用（Node/Python）——需要额外运行时，与"零安装依赖"目标冲突，放 v2 评估
- 自动更新（当前手动替换 exe）

## 7. v1.0.3 生成链路的已知边界（重要）

| # | 项 | 说明 |
| --- | --- | --- |
| 27 | **自测不可用时会降级为静态校验** | 测试机/受限环境里 WebView2 起不来（`COMException 灾难性故障 0x8000FFFF`、建窗 15s 超时等）时：重试一次 → 仍不行就只做静态校验（入口文件存在、含 `data-app-root`、有可见文字与脚本），并在版本备注和结果面板标注「未真跑页面」。**这类应用请在打开后自行确认一遍**。注意：如果此前真实自测已经发现过代码问题，则不会降级通过（宁可报错也不入库坏应用） |
| 28 | 轮次预算不是无限 | 新建 16 轮 / 修改 12 轮；需求超过 150 字或含"统计、图表、设置、导入、导出"等复杂关键词时 +10 轮，硬上限 40 轮。真的用尽时会用"当前已有文件"继续自测，并在版本备注里写「轮次用尽，未显式收尾」 |
| 29 | 模型可能"原地打转" | 该网关的模型偶尔会把同一个文件整篇重写多轮（实测连写 16 轮）。引擎有防打转保护：当入口文件已完整（含脚本）且某轮只是整篇重写已有文件、没有新文件/追加时，直接收尾进自测。副作用是"模型下一轮本来想再优化一下"的机会会被跳过 |
| 30 | 大文件优先拆文件而不是分段追加 | 单轮输出上限 16000 tokens（约 400~600 行）。超出时会提示模型拆成 `index.html` + `style.css` + `app.js` 分别写完整文件，而不是"写一半再 append"，避免出现"只有静态界面、没有 JS"的半成品 |
| 31 | 生成耗时与环境有关 | 开发机实测：简单应用 50~80 秒（含自测），复杂应用 3~5 分钟；其中模型每写一个 8KB 文件约 20~30 秒，自测正常 1~3 秒（WebView2 不可用时每次降级检测约 15 秒） |
| 32 | 「打开目录」依赖系统资源管理器 | 程序会依次尝试：系统外壳调用 → `explorer.exe` → `rundll32 FileProtocolHandler`。**如果这台机器上 explorer.exe 根本起不来（精简系统/无交互外壳的会话/被安全策略限制，典型报错 0xC0000142 `STATUS_DLL_INIT_FAILED`）**，三种方式都会失败，此时程序会把路径复制到剪贴板并提示"没能调起资源管理器"。这是环境限制，不是数据问题——路径照样可以手动粘贴到资源管理器或另存。程序已关闭系统级错误弹窗，不会再甩一个 `explorer.exe - 应用程序错误` 的框；首选走 shell32 的 `SHOpenFolderAndSelectItems`（不新起进程），最后兜底是**应用内文件列表**（`fs.list`，只读、限制在数据目录内），所以「打开目录」在任何环境都至少能让你看到文件。自查命令：`AppForge.exe --open-folder="<路径>"`（输出 `ok` / `copied`，日志里记录每一级的失败原因） |
| 33 | 上游网关的瞬时故障会重试一次 | 网关（frp/反代）在隧道不通时可能返回 404/502/503，甚至整页 HTML。这类错误按"瞬时可重试"处理：自动重试 1 次；仍失败会给出清洗过的提示（不含 HTML 源码）并建议稍后重试或换网关。真实的地址填错也会落到这里，看到"HTTP 404"时先检查设置页的 Base URL |
| 34 | 首次运行可能弹 SmartScreen「已保护你的电脑」 | 这是 Windows 对**没有代码签名**（发行者未知）程序的通用提示，与「打开目录」的 0xC0000142 无关，是两件独立的事。处理方式：点「更多信息 → 仍要运行」；或右键 exe → 属性 → 勾选「解除锁定」→ 确定（等价于 Unblock-File）。要彻底消除只能购买代码签名证书并给 exe 签名，或用 winget/MSIX 分发 |
| 35 | SmartScreen 提示的三种解法（v1.0.5 起内置） | ① 双击产物里的「首次运行-点我（解除SmartScreen提示）.cmd」；② 右键 AppForge.exe → 属性 → 勾选「解除锁定」→ 确定；③ AppForge.exe --unblock。程序每次启动也会自动清掉自身标记，所以成功启动一次后不再提示。**彻底消除只能购买代码签名证书并对 exe 签名**（或用 winget/MSIX 分发），这不是代码层面能绕过的 |
