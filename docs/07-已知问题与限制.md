# AppForge 已知问题与限制（v1.0）

> 原则：**失败必须可见、可修、可回滚，且不污染已有应用。** 下面这些是当前版本明确已知的边界。

---

## 1. 交付形态

| # | 项 | 说明 |
| --- | --- | --- |
| 1 | 单文件首次启动稍慢 | 单文件是"启动器 + 压缩包"，首次运行需把 payload **在内存中解压**到可写目录（约 1 秒），之后复用不再解压 |
| 2 | 单文件不是"免解压单进程" | 解压后的真身仍是普通 exe（在同目录），这是 .NET Framework 下不引第三方打包器的取舍 |
| 3 | **SmartScreen 未签名提示** | 程序未购买代码签名证书，Windows 可能提示"无法识别的应用"。处理：更多信息 → 仍要运行，或 `Unblock-File`。**想避免就优先用绿色便携包** `dist\AppForge-portable.zip` |
| 4 | 受限目录会自动换位置 | 若 `%LOCALAPPDATA%` / `%TEMP%` 被策略或杀软限制，程序自动回退到 exe 同目录并记日志（`logs\launcher.log`），不会直接启动失败 |
| 5 | 便携数据目录 | 默认数据在 `%LOCALAPPDATA%`；如需 U 盘便携，用 `--data-dir=<路径>`（或在 exe 同目录放 `portable.flag`） |
| 6 | 未做自动更新 | 升级 = 换掉 exe / 解压新便携包，数据目录不变即可继承 |

## 2. 兼容性

| # | 项 | 说明 |
| --- | --- | --- |
| 5 | 最低系统 | Windows 10 22H2（19045）+ / Windows 11 x64。低于此版本会明确提示并不启动 |
| 6 | WebView2 依赖 | Win11 自带；Win10 多数随 Edge 预装；缺失时首启自动静默安装（需联网）。企业禁用安装时可用"选择离线安装包"或降级为仅逻辑模式 |
| 7 | 高 DPI | 已适配 PerMonitorV2（200% 缩放下布局正确）；但**高 DPI + 大窗口下 WebView2 内存偏高**（本机 200% 缩放实测：宿主 54MB + WebView2 子进程合计约 390MB）。普通 100% DPI 机器会明显更低，后续版本会缩小默认窗口并复核 |
| 8 | 双机验收 | 单文件版已在开发机（Win11 26200）完整验证；**干净 Win10/Win11 虚拟机的安装/卸载验收仍待执行**（需要真实虚拟机环境） |

## 3. 生成能力边界

| # | 项 | 说明 |
| --- | --- | --- |
| 9 | 目标形态 | v1 聚焦**单页静态应用**（HTML/CSS/JS，离线可跑、`localStorage` 持久化）。不做后端、不做需要构建/多依赖的复杂前端工程 |
| 10 | 规模上限 | 单文件 ≤1200 行 / ≤200KB，总文件 ≤8，生成阶段单文件写入 ≤400KB（超限会拒绝并提示模型收敛） |
| 11 | 模型要求 | 需要支持 `tools`（function calling）的模型；不支持时会给明确报错并建议换 `gpt-4o-mini` |
| 12 | 修复次数 | 自测失败自动修复最多 3 轮；仍失败则给出可读诊断（页面报错、body 长度、`data-app-root` 检测结果），**不产生坏应用** |
| 13 | 并发 | 同一时间只跑 1 个生成/修改任务（避免草稿互相污染），并发请求会返回"已有任务在进行中" |
| 14 | 修改上下文 | 修改模式会注入现有文件全文（单文件 40K、总量 240K 字符，超出截断）；超大应用可能改不全 |
| 15 | 生成期间关窗口 | 会取消任务并清理草稿（自测依赖同进程 WebView2）。这是预期行为，但请注意不要在关键步骤关闭 |

## 6. 已知但暂不做的功能

- 多端同步 / 账号体系（纯本地单用户）
- 应用商店 / 一键分享链接（当前用 zip + 快捷方式）
- 应用内二次开发的可视化编辑器（以自然语言 + 代码只读视图为主）
- 脚本类应用（Node/Python）——需要额外运行时，与"零安装依赖"目标冲突，放 v2 评估
- 自动更新（当前手动替换 exe）

## 7. v1.0.3 生成链路的已知边界（重要）

| # | 项 | 说明 |
| --- | --- | --- |
| 27 | **自测不可用时会降级为静态校验** | 测试机/受限环境里 WebView2 起不来（`COMException 灾难性故障 0x8000FFFF`、建窗 15s 超时等）时：重试一次 → 仍不行就只做静态校验（入口文件存在、含 `data-app-root`、有可见文字与脚本），并在版本备注和结果面板标注「未真跑页面」。**这类应用请在打开后自行确认一遍**。另外 v1.0.7 起白屏判定不再只看固定字符数，而是结合可见文字与可见图形（`canvas/svg/img/video/iframe`），避免误杀只有几个字/几个按钮的小应用。注意：如果此前真实自测已经发现过代码问题，则不会降级通过（宁可报错也不入库坏应用） |
| 28 | 轮次预算不是无限，但不再“到点强收” | v1.0.9 起新建 24 轮 / 修改 16 轮；需求超过 150 字或含“工具箱、助手、统计、图表、设置、导入、导出”等复杂关键词时 +16 轮（工具箱通常从 40 轮起步）。未完成时**每档自动续 16 轮**；160 轮只是防止无限烧钱的安全上限。达到安全上限仍未调用 `done` 时**拒绝保存半成品**，不会再出现“能打开但功能缺一半”的版本。入口完整、文件稳定后还要先做一次**需求完整性核对**，核对通过才允许收尾。该修复只影响新生成、重新生成或继续修改；旧版本已保存的应用不会自动补全，需在「继续修改」里补齐缺失功能，或重新生成 |
| 29 | 模型可能"原地打转" | 该网关的模型偶尔会把同一个文件整篇重写多轮（实测连写 16 轮）。v1.0.9 起只看**内容是否真变**：写入前后逐字节比对，有任何变化就算推进；只有连续 4 轮无任何内容变化、且入口自包含，并且完成前需求核对通过时才收尾。若模型文字里明确出现“还缺 / 未实现 / TODO”等未完成措辞，也不会被当成完成。入口还引用着没写出来的 `app.js`/`style.css` 时，会先催模型补齐，**该状态下不会提前收尾** |
| 30 | 大文件优先拆文件而不是分段追加 | 单轮输出上限 16000 tokens（约 400~600 行）。超出时会提示模型拆成 `index.html` + `style.css` + `app.js` 分别写完整文件，而不是"写一半再 append"，避免出现"只有静态界面、没有 JS"的半成品 |
| 31 | 生成耗时与环境有关 | 开发机实测：简单应用 50~80 秒（含自测），复杂应用 3~5 分钟；其中模型每写一个 8KB 文件约 20~30 秒，自测正常 1~3 秒（WebView2 不可用时每次降级检测约 15 秒） |
| 32 | 「打开目录」依赖系统外壳/资源管理器 | v1.0.8 起依次尝试**多级**，且**每一级都要确认窗口真的出现**才算成功（打开前后用 `EnumWindows` 对比资源管理器窗口）：① `ShellExecuteEx("open")` + `SEE_MASK_FLAG_NO_UI`（由已在运行的资源管理器处理，不新建进程，失败不弹系统框）→ ② `Shell.Application` COM 的 `Navigate2`（让已在运行的资源管理器新开窗口，独立 STA 线程 + 8 秒超时）→ ③ `SHOpenFolderAndSelectItems`（调用前显式 `CoInitializeEx` STA）→ ④ 自建 `explorer.exe` 进程 → ⑤ `explorer.exe /e` → ⑥ `rundll32 url.dll,FileProtocolHandler`。**全部“报告成功但没等到窗口”时返回失败**，界面降级成应用内文件列表（只读、限制在数据目录内），路径同时进剪贴板。无论调用方是不是 STA，`FolderOpener` 都会切到独立 STA 工作线程，不会冻住 UI。自查：`AppForge.exe --open-folder="<路径>"`，输出里的 `stages` 列出每一级的结果与验证信息，`openedBy` 是最终真的打开了的那一级，`elevated` 表示是否管理员 |
| 32b | 装了安全软件的机器上 explorer 调不起来 / 打开目录没反应 | 若 `--open-folder` 的 `stages` 显示 `explorer: 0xC0000142`、`shellApi: 0x80070005` 或 `shellNavigate` 超时，说明安全软件的「启动防护 / 程序执行控制」在拦资源管理器调用。常见来源：火绒、360、腾讯电脑管家、**联想电脑管家（`wsctrl11.exe` / `usysdiag.exe`）**。v1.0.8 首选 `ShellExecuteEx`（失败不弹系统框），再尝试 COM 导航和其他级别；若多级仍全失败，请把 `AppForge.exe` 或整个安装目录加入该软件的信任区/白名单。程序内置应用内文件列表（设置页「在应用内浏览」）作为兜底，不依赖资源管理器也能看/复制路径。一键判断是谁在拦：`.\scripts\diagnose-env.ps1` |
| 32c | `shellExecute: 失败（Win32 5）` / `shellApi: 0x80070005`，但系统资源管理器本身正常 | 先检查 exe 是否被打了 **Low 完整性标签**。低完整性进程无法把“打开目录”请求交给普通权限的资源管理器，表现就是 Win32 5；常见于在沙箱、云同步目录或某些解压工具生成的文件夹里直接运行。v1.0.8 的打包脚本会自动把 `dist` 和最终 exe 提升到 Medium。手工修复：`icacls "<AppForge.exe 的完整路径>" /setintegritylevel Medium`；若整个绿色目录都被标成 Low，用 `icacls "<目录>" /setintegritylevel "(OI)(CI)Medium" /T /C`。 |
| 33 | 上游网关的瞬时故障会重试一次 | 网关（frp/反代）在隧道不通时可能返回 404/502/503，甚至整页 HTML。这类错误按"瞬时可重试"处理：自动重试 1 次；仍失败会给出清洗过的提示（不含 HTML 源码）并建议稍后重试或换网关。真实的地址填错也会落到这里，看到"HTTP 404"时先检查设置页的 Base URL |
| 34 | 首次运行可能弹 SmartScreen「已保护你的电脑」 | 这是 Windows 对**没有数字签名**（发行者未知）程序的通用提示，与「打开目录」的 0xC0000142 无关，是两件独立的事。**前提**：这类拦截只对带「来自 Internet」标记（MOTW，从浏览器/聊天工具保存的文件才会有）的程序生效——本机自己构建的 exe **本来就不该弹**；如果弹了，先跑 `.\scripts\diagnose-env.ps1` 看是 MOTW、Smart App Control，还是第三方安全软件（联想管家/火绒/360 会弹一个很像 Windows 的风险框）。处理：点「更多信息 → 仍要运行」；或右键 exe → 属性 → 勾选「解除锁定」；或 `AppForge.exe --unblock`。要彻底消除只能购买代码签名证书并签名 |
| 35 | SmartScreen / 安全软件提示的解法 | ① 双击产物里的「首次运行-点我（解除SmartScreen提示）.cmd」；② 右键 AppForge.exe → 属性 → 勾选「解除锁定」→ 确定；③ `AppForge.exe --unblock`。v1.0.9 起产物仍建议做代码签名；**本机自用**可用 `scripts/sign.ps1 -CreateSelfSigned` 签本机信任证书；**发给别人彻底不弹**只能购买 OV/EV 证书（EV 签名即生效）。如果蓝色框来自联想电脑管家/火绒/360，签名也挡不住，需把 `AppForge.exe` 或整个目录加入该软件信任区 |
| 36 | 代码签名工具（v1.0.6 新增 `scripts/sign.ps1`） | 用法：`.\scripts\sign.ps1 -Thumbprint "<证书指纹>"` 或 `-Pfx .\cert.pfx` 直接签；`-CreateSelfSigned` 生成自签名证书并导入本机“受信任的根/受信任的发布者”（**只在本机生效**，发给别人仍提示），自签名会自动跳过时间戳，断网也能签；`-UnblockOnly` 只清 Internet 标记。v1.0.9 起单文件启动器会解析 PE 证书目录，签名后仍能正确定位 payload 尾标记 |
| 37 | 数据目录默认位置不可写时会自动换位置（v1.0.6） | 判定标准是"**能不能真的写一个文件**"（`Workspace.ProbeWritable`），不是"能不能建目录"——安全软件常常放行建目录、拦截建文件。回退顺序：`%LOCALAPPDATA%\AppForge` → `%APPDATA%\AppForge` → `%USERPROFILE%\AppForge` → exe 同目录 `data` → `%TEMP%\AppForge\data`。回退时：① 日志第一行会写明新位置和**旧位置写不进去的原始原因**；② 若新目录还没有 `index.json`，会自动从旧位置（含 `AppForge-payload` 下的历史载荷目录）复制一次数据，避免应用"消失"。排查命令：`AppForge.exe --check`，看 `dataDir`（实际用的目录）与 `dataProbe`（每个候选位置的探测结果）。想固定位置就用 `--data-dir=<目录>` 启动。注意：`exe 同目录 data` 是单文件版的载荷缓存目录，**换版本可能被清理**，只在其它位置都不可写时才用 |
| 38 | 单文件版为什么要解压、`AppForge-payload\` 是什么（v1.0.6 起自动清理） | 单文件 exe = 启动器 + payload.zip + 尾标记；WebView2 的原生 dll 无法从内存加载，所以运行前必须先把内部文件解压到磁盘。解压位置优先级：`%LOCALAPPDATA%\AppForge\payload\` → `%TEMP%\AppForge\payload\` → **exe 同目录 `AppForge-payload\`**（前两个不可写时才用，本机就是这种情况）。v1.0.7 起目录名用 **版本号 + payload 长度 + payload 内容 SHA256 前缀**，同一份构建反复运行**复用同一个目录**，内容变化的构建不会误用旧目录；解压完成后写 `.payload-ready`，标记缺失会重新解压，避免把半解压载荷当完整载荷。每次启动会清理同批次的历史载荷目录，但**存过用户数据的目录（`index.json` / `settings.json` / `apps` 下有应用）一律保留**，被运行中实例占用的跳过。核对记录：`dist\logs\launcher.log` 里的 `STAMP` / `CACHE` / `CLEAN`。想让载荷回到用户目录：解决 `%LOCALAPPDATA%\AppForge` 的拦截即可（见 #37） |
| 39 | 不同启动方式看到的数据不一样（v1.0.6 起统一） | 数据目录的解析规则是"能写就行"，回退链里含"exe 同目录"，所以 `启动AppForge.cmd`（dev exe → `bin\Release\data`）和 `dist\AppForge.exe`（单文件 → 载荷目录）会各存一份。现在：① 启动时把选定的目录写进 **`HKCU\Software\AppForge\DataDir`**，任何入口都读同一个值；② 开发/绿色目录场景额外用 **`<repo>\data`**（向上找 `AppForge.sln`），两个入口必然收敛；③ 首次会把其它位置的应用**合并**过来（只补缺、不覆盖），合并后按 `app.json` 重建索引。日志里能看到「合并检查：扫到 N 个…」「已合并…新增 X 个应用」。想换位置：`--data-dir=<目录>` 启动一次即可（会写入指针） |
| 40 | 生成应用的窗口图标 | v1.0.9 起生成应用窗口（标题栏 + 任务栏）使用该应用自己的 emoji 绘制**真正的彩色图标**：程序解析系统 `seguiemj.ttf` 的 COLR v1/CPAL 彩色字形，生成 16～256 多尺寸 ICO，底色与应用卡片一致；标题栏与任务栏共用同一枚图标。彩色渲染失败时自动回退单色图标。主窗口与托盘仍使用 AF 品牌图标，不需要额外 png/ico 文件 |
| 41 | 更新后仍显示旧界面 | v1.0.9 起发布版 UI 缓存在 `<数据目录>\ui\ui-<版本>-<内容指纹>`，指纹是全部内置 JS/CSS/HTML 的 SHA256 前 12 位；任何界面文件变化都会换新目录，旧方案 `ui-<版本>` 会被自动清理。UI 指纹变化时启动还会清空 WebView2 缓存，避免 URL 不变时命中旧 JS。仍看到旧页面时，退出所有 AppForge 实例后重新启动即可，不需要手工清缓存 |

## 8. 反馈问题时请提供

1. 设置页 → **🩺 诊断 → 导出诊断包**（`exports\appforge-diag-*.zip`）
2. 复现步骤（哪一步、什么提示）
3. 系统版本与是否 200% 缩放（设置页 → 关于里有系统信息）
