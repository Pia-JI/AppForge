## 1. 背景与目标

### 1.1 问题陈述

1. **长尾需求无处安放**：批量改文件、按自己规则做记账、盯某个网页变化、生成固定格式报表——这类"只有我用的软件"，商业软件不做，通用软件太重。
2. **AI 能写但留不住**：用对话式 AI 写出来的东西停留在聊天记录里，没有入口、没有图标、没有版本，下次想用还得重来一遍。
3. **能生成不等于能用**：生成结果常缺依赖、报错、样式错乱，普通用户没有能力修复。

### 1.2 产品目标

把"AI 现场写的软件"变成**可收藏、可启动、可迭代、可导出**的本地资产：

> 用户说出需求 → AI 规划并生成 → 自动跑通并自测 → 固化为桌面里的一个应用 → 以后双击秒开 → 不满意回来说一句，AI 增量改。

### 1.3 成功指标（v1 验收用，可埋点量化）

| 指标 | 目标值 | 测量方式 |
| --- | --- | --- |
| 一句话 → 首次可运行应用（P50） | ≤ 60s | run 记录 `first_runnable_ms` |
| 一句话 → 首次可运行应用（P90） | ≤ 180s | 同上 |
| 生成成功率（无需人工干预即能跑） | ≥ 80% | 自测通过率统计 |
| 壳冷启动到桌面首屏可交互 | ≤ 1.0s（P50）/ ≤ 2.0s（硬上限） | `--bench` 打点 |
| 已保存应用双击 → 首屏可交互 | ≤ 500ms（P50）/ ≤ 1.0s（硬上限） | `--bench` 打点 |
| 二次打开触发构建的比例 | 0% | 构建日志 |
| **安装型第三方依赖数量** | **0** | 依赖预算表（04 文档） |
| 交付体积（单 exe） | ≤ 5MB | 打包产物 |
| 应用留存（7 日后仍被打开过） | ≥ 40% | 打开事件 |

### 1.4 非目标（v1 明确不做）

- 不做多端同步 / 云托管 / 应用商店分发（本地优先；导出能力先做好）
- 不做多人协作
- 不做"生成手机 App / 生成后端服务并公网部署"
- 不做可视化低代码编辑器（以自然语言 + 代码视图为主）
- 不追求生成复杂 3D / 游戏 / 大型 SPA（生成规范里明确限制规模）

## 2. 用户与场景

### 2.1 用户画像

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| 小白用户（主要） | 不会写代码，装过 AI 客户端 | 说人话就能得到能用的软件，别让我配环境 |
| 半技术用户 | 会改一点代码，有明确需求 | 生成后能看代码、能微调、能导出 |
| 极客用户 | 用 AI 批量产出小工具 | 快速、可控、可版本、可脚本化 |

### 2.2 关键用户故事

- **US-1**：作为用户，我打开软件看到的是我的"应用桌面"，有我造过的所有小软件，按最近使用排序。
- **US-2**：作为用户，我点"新建"，用一句话描述我要什么，看着 AI 一步步写代码，写完直接能点开用。
- **US-3**：作为用户，我关掉软件明天再打开，昨天造的应用还在，双击就开，不用等编译。
- **US-4**：作为用户，我对某个应用说"把字体调大、加一个导出 CSV"，AI 在原应用上改，改坏了能退回上一版。
- **US-5**：作为用户，我把某个应用导出成 zip / 桌面快捷方式，发给同事。
- **US-6**：作为用户，生成过程卡住或报错时，AI 自己读报错并修复，我在旁边看得见进度。
- **US-7**：作为用户，我能在设置里换模型、填 API Key、改应用存放目录。

### FR-0 零依赖交付与首启自动安装 · P0

> 背景：用户明确要求"尽量减少外部依赖组件，优先用 Windows 自带的；实在必要的外部依赖在软件首次打开时自动装好"。
> 本组需求是**硬性约束**，任何功能设计不得违反。详见 [04 依赖预算与首启安装](04-依赖预算与首启安装.md)。

| 编号 | 需求 | 优先级 | 验收口径 |
| --- | --- | --- | --- |
| FR-0.1 | 交付物为**免安装绿色包**：单 exe（或 exe + 极少文件），双击即用，不需要安装程序、不需要管理员 | P0 | 干净虚拟机拷贝即启动成功 |
| FR-0.2 | 运行时组件全部来自 Windows 自带：.NET Framework 4.8、WinForms、WebView2 运行时 | P0 | 依赖预算表逐项标注来源，无第三方运行库 |
| FR-0.3 | **安装型第三方依赖 = 0**；任何新增依赖必须先更新依赖预算表并说明理由 | P0 | 代码评审门禁（03 §4） |
| FR-0.4 | 启动时做依赖自检（OS / .NET / WebView2 / 数据目录可写），全部通过则在 **10ms 内**放行，不拖慢首屏 | P0 | `--bench` 显示自检耗时 |
| FR-0.5 | WebView2 缺失时：原生引导窗 + **一键静默安装**（内嵌 2MB 官方引导器，用户级安装，无管理员） | P0 | 卸载运行时的虚拟机上可自动装好并重启可用 |
| FR-0.6 | 无网络时提供离线安装包导入入口 + 官方下载链接 + 明确错误码 | P0 | 断网场景有可操作提示 |
| FR-0.7 | 安装失败时提供"降级模式"：不渲染 UI 也能导出/备份用户数据 | P1 | 引导页可选进入 |
| FR-0.8 | 依赖状态可查：设置页显示各组件版本与修复入口 | P1 | 显示 WebView2/.NET 实际版本号 |
| FR-0.9 | 单 exe 体积 ≤ 5MB，空闲内存 ≤ 150MB，磁盘占用 ≤ 15MB | P0 | 打包产物与任务管理器实测 |
| FR-0.10 | 卸载 = 删目录；不写注册表（开机自启项除外且可控） | P0 | 删除后无残留进程/项 |

## 4. 非功能需求（NFR）

### 4.1 性能预算（这是本产品的核心竞争力，必须逐项打点验收）

**A. 壳冷启动（进程启动 → 桌面首屏可交互）**

| 阶段 | 预算 | 手段 |
| --- | --- | --- |
| 宿主进程初始化（CLR + WinForms） | ≤ 150ms | `Main` 只做单实例检查、依赖自检、建窗；其余全部懒加载 |
| 依赖自检（.NET / WebView2 / 目录可写） | ≤ 10ms | 读注册表 + `GetAvailableBrowserVersionString`，无网络 |
| **原生启动画面可见** | **≤ 800ms（硬断言）** | 窗口先显示原生画面，不让用户面对"点了没反应"（M1 实测 108ms） |
| WebView2 环境创建 | ≤ 600ms | 共享环境 + Shell UI 内嵌资源（零请求）（M1 实测 ~430ms） |
| 首次导航 → 首帧 | 0.8–1.5s（普通机）/ 2–3s（无 GPU 或高 DPI 慢机） | Chromium 渲染进程冷启动成本，非本项目代码；M3 用预热池优化二次启动 |
| 读取应用索引（`index.json`） | ≤ 30ms | 一次读全量进内存（数百应用 ≈100KB）（M1 实测 77ms 含首次种入） |
| **合计（普通机 P50 / 硬上限）** | **≤ 1.5s / ≤ 4.0s** | `--bench` 断言"启动画面 ≤800ms"，首帧仅信息性；实测数据见 05 文档 §9.4 |

**B. 已保存应用启动（点击 → 应用首屏可交互）**

| 场景 | 预算 | 手段 |
| --- | --- | --- |
| 静态 Web 应用（主路径，命中预热窗口） | ≤ 500ms | 免构建产物 + 共享 WebView2 环境 + 预热池复用 |
| 首次打开（未预热，需初始化 WebView2） | ≤ 1.0s | 启动后空闲预热，通常首次点击时已就绪 |
| 需构建的应用（首次 / 之后） | 3–20s / ≤ 600ms | 首次构建后产物固化，永远不再构建 |
| 脚本类（Node/Python，P1） | ≤ 1.5s | 解释器预热（可选） |

**C. 生成耗时（从提交需求到可运行）**

| 场景 | 目标 | 说明 |
| --- | --- | --- |
| 单文件小工具（计算器/待办/番茄钟） | ≤ 60s（P50） | 1 轮生成即跑通 |
| 多文件静态应用（5–10 文件） | ≤ 120s | 含一次自测修复 |
| 含依赖/构建的框架应用 | ≤ 240s | 仅高级用户主动选择 |
| 首 token 延迟 | ≤ 2s | 流式可见，避免"假死" |

**D. 交互流畅度**：列表滚动 60fps；输入回显 ≤ 16ms；搜索 ≤ 50ms；对话流式追加不卡顿（虚拟滚动）。

### 4.2 可靠性

- 生成过程中杀进程/断电：重启后 run 标记 `aborted`，工作区草稿可继续，不产生坏版本。
- 所有落盘写入采用"临时文件 + 原子替换（`File.Replace`）"，避免半截文件。
- 宿主崩溃不影响已保存应用（应用是普通目录 + JSON 索引即可重建）。
- `index.json` 每日自动快照 1 份，保留 7 份；索引损坏时从 `apps/*/app.json` 重建。

### 4.3 安全与隐私

- 默认**纯本地**：应用代码、对话、数据不上传；仅把"需求与相关代码片段"发给所选模型服务。
- API Key 用 Windows DPAPI（`ProtectedData`，CurrentUser）加密，仅内存解密；日志不记录 Key 与完整请求头。
- 生成的应用运行在独立 origin（`app-<id>.appforge.local`），**拿不到任何宿主 API**，只能读自己的版本目录。
- 生成代码允许使用 `fetch`（部分应用确需联网），但**必须**满足：①应用联网行为可被用户感知（首次触发时提示）；②宿主绝不向应用上下文注入任何密钥或凭据；③生成期内拉取的外链资源不得写入最终产物（保证离线可跑）。
- 危险操作（删目录、`format`、`del /s`、访问工作区外路径）需显式确认。

### 4.4 兼容与体积

- 支持 Windows 10 22H2（19045）+ / Windows 11 x64；高 DPI（125%/150%/200%）不糊。
- **免安装交付**：单 exe ≤ 5MB，磁盘占用 ≤ 15MB（不含用户生成的应用数据），常驻内存（无应用窗口）≤ 150MB。
- **安装型第三方依赖为 0**：.NET Framework 4.8、WinForms、WebView2 运行时均为 Windows 自带；WebView2 极少数缺失时首启静默安装（FR-0.5）。
- 离线可用：桌面、已保存应用、版本管理全部离线；只有"生成/修改"需要联网。

### 4.5 可维护性

- C# 严格编码规范（`-warnaserror` 关键项、无静默 catch）；宿主/共享契约/测试三工程分包；RPC 有单一方法表来源。
- 断言测试覆盖核心纯逻辑（存储与原子写、manifest 校验、路径守卫、版本策略、SSE 解析）≥ 70%。
- 端到端：内置 `AppForge.exe --selftest`（mock 模型）覆盖"启动 → 生成 → 自测 → 保存 → 重启 → 打开 → 回滚"。
- 性能基准：`AppForge.exe --bench` + `scripts/bench.ps1` 进 CI，超出预算即失败。
- **依赖门禁**：新增任何第三方依赖需先更新 04 文档的依赖预算表并通过评审。

## 5. 领域模型与术语

| 术语 | 定义 |
| --- | --- |
| **App（应用）** | 一个用户需求的持久化产物：目录（源码+产物）+ 元数据 + 版本历史 |
| **Version（版本）** | 应用在某一时刻的完整快照，自测通过才生成，编号 v0001 递增 |
| **Run（生成任务）** | 一次"需求 → 产物"的执行记录（含步骤、日志、token、耗时、结果） |
| **Draft（草稿）** | 未跑通/未固化的生成产物，存放于 `drafts/`，可继续或丢弃 |
| **Builder（工作台）** | 对话 + 进度 + 代码 + 预览的生成界面 |
| **Launcher（启动桌面）** | 应用卡片墙，产品的主入口 |
| **manifest.json** | 应用清单，壳启动应用的唯一契约（类型/入口/窗口尺寸/能力） |
| **免构建产物** | 可直接由宿主加载的静态产物（HTML/JS/CSS），是"秒开"的关键前提 |
| **预热池** | LRU 保留最近几个已加载应用窗口，实现亚秒级二次打开 |
| **虚拟主机（origin）** | 每个应用分配 `app-<id>.appforge.local`，浏览器按 origin 隔离存储，应用间数据互不干扰 |
| **依赖自检** | 启动时毫秒级检查 .NET / WebView2 / 目录可写，缺失则进入首启安装引导（FR-0） |

## 6. 约束与假设

1. 假设用户机器可联网（生成阶段），且已有可用大模型 API Key；无 Key 时提供"体验模式"（内置 3 个示例应用，可点开、不可生成）。
2. 生成质量受模型能力约束：v1 以"小而美的单页/本地静态应用"为主要目标形态，复杂应用允许失败并给出诊断与降级建议。
3. 不承诺生成结果 100% 正确；承诺"失败可见、可修、可回滚、不污染已有应用"。
4. 生成的 Web 应用运行在 WebView2（Windows 自带的 Chromium 内核）中，可用现代 CSS/JS API，不需要 polyfill。
5. 宿主运行时依赖 Windows 自带的 .NET Framework 4.8；低于 Win10 22H2 的系统不支持（首启明确提示）。
6. WebView2 运行时缺失时由软件首启自动安装（用户级、静默、无需管理员）；企业环境禁止安装时提供离线导入与"降级模式"。
7. 验收约束：WebView2 依赖命名管道与桌面会话，**GUI 类验收必须在真实桌面执行**；受限沙箱内只能跑逻辑层测试（数据/校验/提示词/解析）。
