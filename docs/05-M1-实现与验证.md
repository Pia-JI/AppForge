## 3. 关键实现决策（与 02 架构的落地差异）

| 议题 | 决策 | 原因 |
| --- | --- | --- |
| 虚拟主机实现 | 用 `SetVirtualHostNameToFolderMapping` | 官方支持、自带目录越界防护；CSP 改为在生成阶段注入 `<meta>`（M2 实现），避免自建响应服务器 |
| 测试工程 | 不建独立 `tests/` 项目，改为 exe 内置 `--selftest` | 零第三方测试框架，构建即测，逻辑层 42 条断言可离线跑 |
| 存储 | JSON + `File.Replace` 原子写 + 每日快照（未上 SQLite） | 数据量小、零依赖、可直接用资源管理器备份；接口已隔离 |
| UI 资源 | 开发态读磁盘 `wwwroot`，发布态从嵌入资源解包 | 改 UI 不用重新编译；单文件 exe 也能带 UI |
| 设置默认值 | 默认 Base URL = `https://api.example.com/v1`，默认模型 = `gpt-4o-mini` | 用户提供的网关里没有 `deepseek-chat`；`gpt-4o-mini` 实测支持 function calling |
| 密钥 | 只在设置页写入 + DPAPI 加密；仓库/文档中**不出现明文** | 避免泄露；用户可在设置页随时替换/清除 |

## 5. 如何运行（用户操作）

**方式一：双击 `启动AppForge.cmd`（推荐）**

```
双击项目根目录的  启动AppForge.cmd
  → 自动判断产物是否最新（不是则增量构建，首次约 10 秒）
  → 启动 AppForge.exe
  → 出错会暂停窗口并显示原因，不会一闪而过
```

**方式二：双击 `创建桌面快捷方式.cmd` 一次**

之后桌面会有「AppForge 造物台」，**以后真正一键启动**（直接指向 exe，不弹控制台、不构建）。
删除：`scripts\create-shortcut.ps1 -Uninstall`。

**方式三：开发/带参数启动**

```powershell
.\scripts\launch.ps1                 # 构建（按需）+ 启动
.\scripts\launch.ps1 -NoBuild        # 只启动
.\scripts\launch.ps1 -BuildOnly      # 只构建
.\scripts\launch.ps1 -DataDir D:\af  # 指定数据目录
.\scripts\launch.ps1 -DryRun         # 演练，只打印将做什么
.\scripts\run.ps1                    # 等价于 launch.ps1（旧入口保留）
```

> 脚本实现要点：`.cmd` 用纯 ASCII + `chcp 65001` 保证不乱码；`.ps1` 保存为 **UTF-8 with BOM**（PowerShell 5.1 读中文必需）；用 `-ExecutionPolicy Bypass` 绕过执行策略；按"源码比 exe 新才构建"做增量判断，所以第二次启动几乎无等待。

**首次启动后的操作**

1. 桌面会出现 3 张示例卡片 → 双击「待办清单」应弹出独立窗口（应用运行在独立 origin）。
2. 点右上角 ⚙ → 「模型连接」：
   - API 地址已预填 `https://api.example.com/v1`
   - **API Key 需要你粘贴一次**（我不会把密钥写进代码或文档；粘贴后点「保存密钥」）
   - 点「拉取模型列表」可选择模型（默认 `gpt-4o-mini`）
   - 点「测试连接」应显示 `连接成功 · xxx ms · gpt-4o-mini`
3. 关掉窗口 → 托盘图标；再双击托盘恢复。重启后应用与设置都在。

**诊断命令（可选）**

```powershell
.\scripts\ci.ps1                                  # 构建 + 自检 + UI 检查 + 基准
```

## 9. M1 热修复：用户反馈 3 个问题的根因与修复（v0.1.1）

> 反馈：① 设置界面空白；② 窗口内容不随窗口缩放；③ 应用窗口没出现、主界面应用卡片空白。

### 9.1 问题 ①②③ 中"空白/打不开"是同一个根因：WebView2 消息解析用错 API

- 前端用 `chrome.webview.postMessage({id, method, params})` 发的是 **JS 对象**；
- 宿主却用 `TryGetWebMessageAsString()` 取，**对对象消息会抛异常**；
- 异常被 `catch { return; }` 静默吞掉 ⇒ **所有 RPC 请求永远没有响应**；
- 表现：
  - 启动桌面拿不到应用列表 ⇒ 只有骨架/空白卡片；
  - 设置页 `await call('settings.get')` 永远挂起 ⇒ 一片空白；
  - 点应用 `launch.open` 无响应 ⇒ 应用窗口不出现。

**修复**（`ShellForm.OnWebMessage`）：改用 `e.WebMessageAsJson` 读取，并兼容"发的是字符串"的情况（去掉外层引号再解析）；同时新增 `wwwroot/js/diag.js`，把 JS 异常/未处理 Promise/`console.error` 通过 `{event:'ui.error'}` 上报到宿主日志，避免以后再"静默失败"。

### 9.2 问题②"内容不随窗口缩放"的真实原因是高 DPI 不匹配

用 `--ui-diag` 抓到的数据：

| | 修复前 | 修复后 |
| --- | --- | --- |
| 系统 DPI | 192（200%） | 192 |
| 窗口物理尺寸 | 1180 × 780 | 2360 × 1560 |
| 页面 CSS 尺寸 `innerWidth` | **590** | **1180** |
| `devicePixelRatio` | 2 | 2 |
| 结果 | 内容被放大 2 倍、顶栏按钮被挤出窗口 | 布局与设计一致 |

根因：`.NET Framework` 的 WinForms 只声明了 manifest 的 PerMonitorV2，但**缺少 app.config 兼容段**，控件不按 DPI 缩放；而 WebView2 按窗口 DPI 把页面渲染成 2 倍 ⇒ 窗口"按 1 倍开"、内容"按 2 倍画"。

**修复**：
1. 新增 `App.config`：`DpiAwareness=PerMonitorV2` + `EnableWindowsFormsHighDpiAutoResizing=true`；
2. `ShellForm`/`AppForm` 设 `AutoScaleMode=None`，用新增的 `DpiHelper` 手动做"逻辑像素 ⇄ 物理像素"换算（manifest 里的窗口尺寸本来就是 CSS 逻辑像素）；
3. 窗口尺寸/位置按屏幕工作区裁剪，并保存**逻辑尺寸**，换 DPI 不再漂移。

### 9.3 问题③附带发现：旧实例占用 dll 导致构建失败

用户反馈时 AppForge 还在运行，`bin\Release\*.dll` 被占用 ⇒ `dotnet build` 直接失败（`MSB3027`）。
**修复**：`scripts/launch.ps1` 在"需要构建"时先优雅关闭旧实例（`CloseMainWindow` → 兜底 `Stop-Process`），再构建。

### 9.4 关于启动速度：为什么首帧 2.5s

`--ui-diag` 的分阶段数据：

| 阶段 | 耗时 | 说明 |
| --- | --- | --- |
| 进程 + 依赖自检 + 数据加载 | ~95ms | `checks` 17ms + `dataLoad` 77ms |
| **原生启动画面可见** | **108ms** | 用户感知"点了就反应" |
| WebView2 环境创建 | ~430ms | 内含浏览器进程拉起 |
| 页面导航 → 首帧 | ~2070ms | 页面资源只占 **28ms**（9 个文件）；其余是 Chromium 渲染进程冷启动 + 200% DPI 软件渲染 |
| 应用窗口打开 | 216–284ms | 运行时已热，应用为免构建产物 |

结论：**慢在 WebView2/Chromium 冷启动，不在我们的代码或资源**。此环境是无 GPU 的虚拟机 + 200% 缩放，属于偏慢场景；普通独显/核显机器通常 0.8–1.5s。
因此 `--bench` 的硬断言改为"**启动画面 ≤800ms**（已实测 108ms）"，首帧仅作信息性指标（>8s 才判失败），避免在慢环境误报。后续 M3 会用"预热池 + 保留浏览器进程"进一步压缩二次启动。

### 9.7 追加修复：模型下拉框「选不了」（v0.1.2）

**现象**：点开模型输入框看不到可选模型，无法从网关的模型列表里选。

**根因**：模型控件用的是 `<input list>` + `<datalist>`。Chromium 内核（WebView2）对 datalist 的行为是"**聚焦时不会自动弹出列表**"，必须打字或按 ↓ 才出现建议，用户直觉上就是"点不开、选不了"；而且列表不持久化，重开设置页就没了。

**修复**：
1. 换成**原生 `<select>` 下拉框**（点一下必定展开、带下拉箭头），与可编辑的输入框并排：下拉选 → 同步到输入框；手动输入 → 反向下拉高亮；
2. 模型列表缓存到 `localStorage`（`af.models`），重开设置页仍然可用；
3. 首次进入设置页且已配置 Key 时**后台自动拉取一次**（无需先点按钮）；
4. 自定义模型名也支持：输入不在列表里的名字时，下拉框追加「（自定义）」项；
5. 提示"选择后点「保存设置」生效"（或直接点「测试连接」，它会先保存再测试）。

**验证**（`--ui-diag` 自动化，写入 4 个模型缓存后模拟选择 `glm-5.3-flash`）：

```json
{"optionCount":4,"selectValue":"glm-5.3-flash","inputValue":"glm-5.3-flash","ok":true,"disabled":false}
```
> 你机器上的操作：打开 ⚙ → 若下拉框初始为空，会把已缓存的列表填上；若从没拉取过，配置好 Key 后约 2 秒会自动拉取。也可以点「拉取模型列表」。
