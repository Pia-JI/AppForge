# 02 · 架构设计

- 版本：v0.2（依据"最小化外部依赖"要求重构技术栈，v0.1 的 Electron 方案已废弃）
- 关联：[01 需求](01-需求规格说明书.md) · [03 任务规划](03-任务规划与里程碑.md) · [04 依赖预算](04-依赖预算与首启安装.md)

---

## 1. 设计原则

| 原则 | 落地方式 | 为什么 |
| --- | --- | --- |
| **只用 Windows 自带件** | 宿主 = .NET Framework 4.8 + WinForms（系统内置）；渲染 = WebView2（系统内置）；HTTP/JSON/加密/进程/截图全用 BCL | 用户不需要装任何东西，绿色即用 |
| **唯一例外要能自愈** | WebView2 缺失 → 首启静默安装（内嵌 2MB 引导器） | 极少数 Win10 机型缺失，不能让用户卡死 |
| **产物优先于框架** | 生成物默认是免构建静态产物，宿主只负责加载 | 秒开的根因不是优化代码，而是**没有构建** |
| **契约先行** | 宿主 ⇄ UI ⇄ 生成物之间只认三样：RPC 方法表、`manifest.json`、工作区目录约定 | AI 只要产出符合契约的文件就能跑 |
| **一次构建，永久缓存** | 构建产物固化进版本目录，二次打开 0 构建 | 用户感知的"打开快"来自零等待 |
| **失败不污染** | 草稿区与正式库物理隔离；版本只在自测通过后创建 | AI 一定会出错，架构必须假设它会出错 |
| **不可信代码当沙箱内容** | 用户应用跑在独立 origin，拿不到宿主能力 | 生成的代码不可信 |
| **一切可导出** | 应用 = 普通目录 + 普通文件，元数据可重建 | 不锁定用户资产 |
| **分层可替换** | 存储、模型、应用类型、打包方式都是接口 | 升级不推翻架构 |

## 2. 技术选型

### 2.1 为什么弃用 Electron（v0.1 方案）

Electron 会把 Chromium + Node 整包分发（安装后 150MB+，内存常驻 200MB+），**与"优先用 Windows 自带组件"直接冲突**。功能上虽然最省事，但代价正是用户明确要避免的东西。

### 2.2 候选方案对比

| 方案 | 运行时依赖 | 需安装？ | 交付体积 | 冷启动 | 开发效率 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **C# + WinForms + WebView2** | .NET Framework 4.8（Win 内置）+ WebView2（Win11 内置） | **否** | **≈1MB（实测）** | 0.5–1.0s | ★★★★ C# + 原生 Web UI | **采用** |
| C++ + Win32 + WebView2 | WebView2 | 否 | ≈0.5MB | 0.3–0.6s | ★★ 内存/COM 手工管理，迭代慢 | 只追求极限体积时备选 |
| Tauri 2 | WebView2（同左）+ 需 Rust 构建链 | 否 | ≈5MB | 0.4–0.8s | ★★★ Rust + 前端，AI 代码生成风险高 | 不采用 |
| .NET 8 self-contained | 自带运行时 | 否（自带） | 70–150MB | 0.4–0.8s | ★★★★ | 体积与要求冲突，不采用 |
| Electron | 自带 Chromium + Node | 否（自带） | 150MB+ | 1.0–2.5s | ★★★★★ | **弃用** |

**选择理由**：本产品的三个技术难点是「AI Agent 编排 + 文件/进程工具链」「不可信的网页内容沙箱运行」「高频 UI 迭代」。C# 解决第一和第三（BCL 现成、WinForms 稳定），WebView2 解决第二（系统级 Chromium，隔离由 origin 保证），而运行时组件**全部来自 Windows 本身**。

### 2.3 具体选型

| 关注点 | 选择 | 说明 / 备选 |
| --- | --- | --- |
| 宿主运行时 | **.NET Framework 4.8**（`net48`） | Windows 内置。备选 .NET 8 self-contained（体积代价） |
| 宿主 UI 容器 | **WinForms** | 比 WPF 轻、启动快；UI 主要在 WebView2 里，WinForms 只做窗口壳 |
| 界面渲染 | **WebView2（Evergreen 运行时）** | 系统自带；固定版本会 +250MB，**不采用** |
| 界面技术 | **原生 HTML/CSS/JS（ES Modules，无构建）** | 零 node_modules、零打包步骤、首屏最快；后续若复杂度上升可引入构建，产物仍是静态文件 |
| JSON | `System.Web.Script.Serialization.JavaScriptSerializer`（BCL） | 若需要高性能/严格解析，自研 200 行解析器；**不引第三方** |
| HTTP/SSE | `HttpClient` + `StreamReader` 手写 SSE 解析 | BCL 自带 |
| 数据存储 | **文件系统 JSON + 原子写 + 每日快照** | 数据量级小（数百应用）；接口预留 SQLite |
| （v2）SQLite | `winsqlite3.dll` P/Invoke（Win10 1607+ 内置） | 数据量大时再上，接口已隔离 |
| 密钥加密 | `ProtectedData`（DPAPI，CurrentUser） | 替代 Electron 的 safeStorage |
| 截图 | `CoreWebView2.CapturePreviewAsync` | AI 视觉自检，零依赖 |
| 测试 | **自研控制台断言运行器**（`tests/` 项目） | 不引 xUnit/NUnit；`dotnet build` 即跑 |
| 打包 | `dotnet build -c Release` + 可选 Costura 内嵌 | **不提供安装器**，绿色 exe |
| 版本控制 | git | 已有 |

> 依赖清单与逐项来源见 [04 依赖预算与首启安装](04-依赖预算与首启安装.md)。**唯一的第三方代码是 WebView2 的 3 个托管桥 dll（≈0.8MB），随包内嵌，不需要安装。**

## 3. 总体架构

```
┌───────────────────────────────────────────────────────────────────────────┐
│                     AppForge.exe（C# / .NET Framework 4.8）                │
│                                                                           │

│  │ ShellForm       │ │ AppForm × N     │ │ PreheatPool（隐藏窗口预热）   │ │

│  │ 应用/对话   │ │ Service    │ │ + Secrets  │ │ 结构化审计(JSONL)      │  │
│  └────────────┘ └────────────┘ └────────────┘ └───────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ GenerationEngine：Planner → Coder → SelfTester → RepairLoop → Finalize│  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ ToolBus：fs.* / proc.run / web.assert / web.screenshot / finalize     │  │
│  │  ← SandboxPolicy（路径/命令分级） + AuditLog                          │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ IModelProvider：OpenAI 兼容（自建网关/OpenAI/Ollama）SSE 流式 + tools │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ 宿主进程外：WebView2 运行时（系统自带）
        ┌───────────────────────┴────────────────────────┐
        │                                                │
┌───────▼────────────────────┐          ┌────────────────▼──────────────────┐
│ shell.appforge.local        │          │ app-<appId>.appforge.local        │
│ Shell UI（内嵌资源）         │          │ 用户生成的应用（版本目录）         │
```

**一句话**：`AppForge.exe` 是 OS 层（窗口、存储、进程、AI 编排、权限），WebView2 负责所有像素，生成的应用被当作不可信网页跑在独立 origin 上。层间只有三个契约：**RPC 方法表**、**manifest.json**、**工作区目录约定**。

## 4. 窗口与进程模型

### 4.1 窗口清单

| 窗口 | 实现 | 生命周期 | 说明 |
| --- | --- | --- | --- |
| Shell 窗口（启动桌面 / 工作台 / 设置） | `ShellForm` + `WebView2` | 常驻，关闭即最小化到托盘（可配置退出） | 单页应用，三个视图切换 |
| 应用窗口 × N | `AppForm` + `WebView2` | 按需 | 一应用一窗口；关闭即销毁 |
| 预热窗口 | 隐藏 `AppForm` | 常驻 1–3 个 | 吸收 WebView2 首次初始化成本 |
| 原生提示窗 | `Form`（无 WebView2） | 临时 | 仅用于 **WebView2 缺失时的安装引导**（此时还没有渲染引擎可用） |

### 4.2 WebView2 环境策略（性能与隔离的平衡）

- **共用一个 `CoreWebView2Environment`**（单一 `UserDataFolder = %LOCALAPPDATA%\AppForge\webview`）
  - 好处：共享浏览器进程/磁盘缓存，第二个应用窗口的创建成本从 ~300ms 降到 ~100ms。
  - 隔离靠 **origin**：每个应用分配独立主机名 `app-<appId>.appforge.local`，`localStorage`/`IndexedDB`/`Cookie` 天然按 origin 隔离且持久化 → 满足 FR-4.2。
  - 升级路径：若未来要跑"明确危险"的第三方应用，可对单个应用改用独立 `UserDataFolder`（代价：多一个浏览器进程 + 首次创建慢）。
- **预热**：Shell 首屏出现后 200ms（空闲时）创建 1 个隐藏 `AppForm` 并初始化 WebView2，把"第一次创建 WebView2"的 ~300–500ms 成本挪到用户无感时。
- **资源回收**：应用窗口关闭 → `Dispose()` 窗口与控件；预热池只保留最近打开且总内存 < 800MB 的 ≤ 3 个。

### 4.3 进程模型

- 单实例：命名互斥量；二次启动带参数（`--open-app=<id>`）时通过 `WM_COPYDATA`（或本地 socket）转交已有实例并退出新进程。
- 生成任务：宿主进程内异步任务（`async/await` + `CancellationToken`），v1 同时只跑 1 个，其余排队。
- 子进程：统一 `ProcRunner`（`Process` + `CreateNoWindow`），带工作目录锁定、超时（默认 120s）、输出上限 2MB、`taskkill /T /F` 杀进程树。

### 5.2 UI（原生 HTML/CSS/JS，无构建）

| 视图 | 内容 | 关键点 |
| --- | --- | --- |
| `launcher` | 应用卡片墙、搜索、新建、右键菜单、空状态 | 首屏只渲染可视区；图标走磁盘缓存 |

## 6. 宿主 ⇄ UI 的通信契约

WebView2 自带 `postMessage` 通道，比 Electron 的 contextBridge 更简单：

```js
// UI 侧（shell.appforge.local 内）
const apps = await rpc.call('apps.list', { search: '' });   // → Promise
rpc.on('gen.event', e => appendStep(e));                    // 事件订阅
```

```csharp
// 宿主侧：统一分发，方法白名单 + 参数校验 + 统一错误信封
internal sealed class RpcDispatcher {
    // 只登记方法表中的方法；未登记 → 直接拒绝（不做反射调用）
    // 参数校验：只接受 appId / 相对路径 / 标量，绝不接受绝对路径
}
```

**方法表（v1 主干）**

| 方法 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `apps.list` | `{search?}` | `AppMeta[]` | 桌面首屏数据 |
| `apps.get` / `apps.rename` / `apps.pin` / `apps.delete` / `apps.restore` | `{id, ...}` | `{}` | 应用管理 |
| `apps.export` / `apps.shortcut` | `{id}` | `{path}` | P1：导出 zip / 生成快捷方式 |
| `launch.open` | `{id}` | `LaunchMetrics` | 启动并返回耗时打点 |
| `gen.start` / `gen.cancel` / `gen.continueDraft` | `{appId?, prompt}` | `{runId}` | 生成任务 |
| `gen.event`（宿主→UI 推送） | 事件对象 | — | 步骤/流式 token/错误 |
| `versions.list` / `versions.rollback` / `versions.diff` | `{appId, seq?}` | `VersionMeta[]` | 版本 |
| `settings.get` / `settings.set` / `settings.testModel` | `{patch?}` | `Settings` | 设置与自检 |
| `dep.status` / `dep.install` | `{}` / `{name}` | `DepStatus[]` | 依赖状态与安装（§3.2 引导页也复用） |
| `fs.reveal` / `app.openDataDir` | `{appId}` | `{}` | 交给资源管理器打开目录 |

**安全约束**：
- 只有 **Shell origin**（`shell.appforge.local`）注册了消息处理器；应用窗口根本不注册 → 生成的应用**无法调用任何宿主能力**。
- 所有 `appId` 在宿主校验存在性；相对路径经 `PathGuard` 校验；`proc.run` 经 `SandboxPolicy` 分级。
- 响应信封固定：`{ id, ok, data?, error?: { code, message } }`；异常不外泄堆栈，详细日志写本地。

## 7. 静态资源与沙箱（虚拟主机映射）

**M1 已落地实现**：用 WebView2 官方的 `SetVirtualHostNameToFolderMapping` 把虚拟主机映射到真实目录，而不是自建请求拦截器。

```
https://appforge.local/                  → <UI 目录>            （Shell UI）
https://app-<id>.appforge.local/         → data/apps/<id>/versions/v000N/  （应用内容）
```

- **每个应用一个独立 host** ⇒ 独立 origin ⇒ `localStorage` / `IndexedDB` / `Cookie` 天然隔离且持久化（FR-4.2）。
- **路径安全**：WebView2 会拒绝映射目录之外的路径访问（越界即 404），等于自带目录穿越防护；宿主侧另有 `PathGuard` 兜底。
- **无宿主能力**：应用窗口不注册 `WebMessageReceived`，并关闭 `IsWebMessageEnabled` / `AreHostObjectsAllowed`，生成的应用无法调用任何宿主 API。
- **UI 目录来源**：开发态直接用 exe 旁的 `wwwroot`（改文件即生效）；发布态从**嵌入资源**解包到 `ui\<版本>\`，支撑单文件交付。
- **CSP**：文件夹映射无法注入响应头，因此改为在 **finalize 阶段把 `<meta http-equiv="Content-Security-Policy">` 写进生成应用的 HTML**（M2 落实），语义等价：
  `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'`
  > `'unsafe-inline'` 是为了让 AI 生成的内联样式/脚本可用；`connect-src 'self'` 默认禁外连（应用声明 `capabilities:["network"]` 时放开）。
- **草稿预览**（M2）：`draft-<runId>.appforge.local` → 指向草稿目录（只读），供自测器与用户预览。
- **升级路径**：若将来需要按应用注入响应头/做审计日志，可切换为 `WebResourceRequested` 自建响应（代码量更大，但完全可控）。

## 8. 数据模型

### 8.1 存储选择

| 方案 | 结论 |
| --- | --- |
| **文件系统 + JSON/JSONL**（采用） | 数据量级小（数百应用、数千消息），零依赖，可直接用资源管理器查看/备份/迁移 |
| SQLite（`winsqlite3.dll`，系统自带） | 数据量变大后升级；`IAppRepository` 接口已隔离，不推翻调用方 |

### 8.2 文件布局

```
%LOCALAPPDATA%\AppForge\                 # 便携模式：exe 同目录 .\data
├─ data\
│   ├─ index.json                        # 应用索引（卡片墙一次读全量）
│   ├─ settings.json
│   ├─ secrets.dat                       # DPAPI 加密的 API Key
│   ├─ backups\index-YYYYMMDD.json       # 每日快照 ×7
│   ├─ audit\YYYYMMDD.jsonl              # 审计
│   ├─ apps\<appId>\
│   │   ├─ app.json                      # 冗余元数据（index 损坏时重建）
│   │   ├─ icon.png
│   │   ├─ messages.jsonl                # 对话，追加写
│   │   ├─ runs.jsonl                    # 生成任务记录
│   │   └─ versions\
│   │       ├─ v0001\{manifest.json, index.html, ...}
│   │       └─ v0002\...
│   ├─ drafts\<runId>\...                # 生成中的草稿（失败即弃/留 7 天）
│   └─ trash\<appId>-<ts>\               # 回收站，7 天清理
├─ webview\                              # WebView2 共享 UserDataFolder
├─ logs\app-YYYYMMDD.log
└─ cache\{icons,thumbs}
```

### 8.3 `index.json` 结构

```json
{
  "schemaVersion": 1,
  "apps": [
    {
      "id": "ap_7f3k2",
      "name": "待办清单",
      "description": "按优先级排序的本地待办",
      "type": "static-web",
      "currentVersion": 3,
      "status": "ready",
      "iconPath": "apps/ap_7f3k2/icon.png",
      "pinned": false,
      "launchCount": 12,
      "lastOpenedAt": 1730000000000,
      "createdAt": 1729000000000,
      "updatedAt": 1730000000000,
      "bytes": 48213
    }
  ]
}
```

- **原子写**：写 `index.json.tmp` → `File.Replace(tmp, dst, backup)`；进程被强杀也不会留下半截文件。
- **重建**：`index.json` 缺失/损坏 → 扫描 `data/apps/*/app.json` 重建（自愈）。
- **迁移**：`schemaVersion` + `DataMigrator` 顺序迁移，升级前自动快照。

### 8.4 应用清单 `manifest.json`（壳与生成器的唯一契约）

```json
{
  "schemaVersion": 1,
  "id": "ap_7f3k2",
  "name": "待办清单",
  "type": "static-web",
  "entry": "index.html",
  "window": { "width": 960, "height": 720, "minWidth": 480, "minHeight": 360, "resizable": true },
  "capabilities": ["storage"],
  "offline": true,
  "build": null,
  "meta": { "model": "gpt-4o-mini", "createdAt": 1730000000000 }
}
```

| 字段 | 约束（`ManifestValidator` 强制） |
| --- | --- |
| `type` | v1 仅 `static-web`；P1 允许 `node-script` |
| `entry` | 必须存在且为文件；`static-web` 必须 `.html` |
| `build` | `null` 或 `{ "cmd": "...", "outDir": "dist" }`；默认 `null`（免构建） |
| `offline` | 必须 `true`（v1 禁外链资源） |
| `capabilities` | 未声明的能力运行时拒绝（当前支持 `storage` / `network` / `clipboard`） |

## 9. 生成引擎（核心难点）

### 9.1 状态机

```
queued
  ├─(1) understand   解析需求，判断是否需澄清（≤1 轮、≤3 个选择题，可跳过）
  ├─(2) plan         结构化作案：应用名/类型/文件清单/交互要点（JSON）
  ├─(3) scaffold     建草稿目录 + 先写 manifest.json（先定契约）
  ├─(4) code         逐文件生成（tool_calls，顺序写盘）
  ├─(5) install      仅当 manifest.build 非空：装依赖（缓存复用；v1 默认不触发）
  ├─(6) build        仅当需要：构建并把产物固化
  ├─(7) selftest     隐藏窗口加载：console error / 未捕获异常 / 白屏 / 根节点断言 / 截图
  ├─(8) repair       失败 → 结构化错误回灌 → 回 (4)，≤3 轮
  └─(9) finalize     提交版本 v000N、更新 index、run 成功
```

任一阶段失败 → `failed` + 人话诊断（技术细节折叠）。**finalize 之前绝不写正式库**，草稿在 `data/drafts/<runId>/`。

### 9.2 工具契约（ToolBus）

| 工具 | 参数 | 说明 | 权限 |
| --- | --- | --- | --- |
| `fs.write` | `path, content` | 写草稿区文件 | 仅当前草稿/应用目录；越界拒绝 |
| `fs.read` / `fs.list` | `path?` | 读文件/列目录 | 同上 |
| `fs.delete` | `path` | 删单文件（不接受递归删目录） | 审计 |
| `proc.run` | `cmd, cwd?` | 白名单/分级执行（`node`/`python`/`git`/包管理器等） | 分级 + 超时 + 审计 |
| `web.assert` | `js` | 在草稿页执行断言脚本（`ExecuteScriptAsync`） | 沙箱 |
| `web.screenshot` | `name` | 截图（`CapturePreviewAsync` → PNG，可回灌给多模态模型） | 沙箱 |
| `finalize` | `note?` | 提交版本（内部调用，AI 不直接调） | — |

所有工具：参数手写校验 + `SandboxPolicy` + `AuditLog`；**AI 只拿相对路径**，绝对路径由宿主拼接。

### 9.3 修复循环

```
for round in 0..3:
    runCodegen()                       // 每轮只允许改"相关文件"
    if needsBuild: runBuild()           // 失败 → 抓 stderr 尾部 200 行
    t = selfTester.run()                // console error / 白屏 / 断言 / 截图
    if t.pass: return finalize()
    if round == 3: return fail(diagnosis)
    prompt += repairPrompt(t)           // 结构化：错误类型 + 文件 + 片段 + 修复要求
```

要点：错误摘要**必须结构化**（否则模型越修越乱）；每轮限定改动范围；3 轮不过即停并给"降级为简单版"建议，避免无限烧 token。

### 9.4 生成规范（写进系统提示词，硬约束）

1. **零构建优先**：单 HTML（内联 CSS/JS）或少量同目录 `.js/.css`；不引 npm 依赖/框架/CDN。
2. **禁止外链**：不得引用 `https://` 资源（图标用内联 SVG/emoji），保证离线可跑。
3. **数据本地化**：持久化只用 `localStorage`，key 前缀 `app:<id>:`。
4. **规模上限**：单文件 ≤ 2000 行，总文件 ≤ 30，单文件 ≤ 300KB。
5. **健壮性**：DOM 操作前判空；初始化包 `try/catch`；不抛未捕获异常。
6. **可自检**：`document.body` 必须有内容，主容器带 `data-app-root`。
7. **风格**：按 manifest 尺寸布局、中文界面、跟随系统深浅色。
8. **禁止**：`eval` 远程代码、读写本地文件、自动下载可执行文件、后台自启。

### 9.5 上下文管理（省 token + 更稳）

| 内容 | 每轮发送 | 说明 |
| --- | --- | --- |
| 系统规则（规范 + 工具契约） | 是（固定前缀） | 前缀稳定利于 prompt cache |
| manifest + 目标结构 | 是 | 小 |
| 文件清单 + 每文件摘要（行数/导出符号/首 20 行） | 是 | 比全量代码省 ~10× |
| 正在修改的文件全文 | 是 | 只展开相关文件 |
| 历史对话 | 压缩（最近 3 轮原文 + 摘要） | 超阈值滚动压缩 |
| 测试错误 | 仅最近一轮结构化摘要 | 避免错误历史污染 |

## 10. "秒开"策略

```
L0 首屏层：启动即骨架屏 + index.json 全量预读 + 图标磁盘缓存
L1 产物层：免构建静态产物 ⇒ 直接导航渲染            ← 决定性的 80%
L2 容器层：共享 WebView2 环境 + 启动后预热 1 个隐藏窗口 + LRU ≤ 3 复用
L3 构建层：需要构建的应用，产物固化后二次打开 0 构建
```

### 10.1 打开时序（静态 Web 应用）

| 时刻 | 事件 | 手段 |
| --- | --- | --- |
| 0ms | 用户双击卡片 | — |
| ~5ms | RPC `launch.open` → 内存索引命中 | 启动时已把 `index.json` 读进内存 |
| ~40ms | 取预热窗口（或新建 `AppForm`） | 预热池 |
| ~120ms | `Navigate("https://app-<id>.appforge.local/")` | 共享环境，无需新建浏览器进程 |
| ~350ms | 首帧渲染 | 产物体积小 + 内联资源 |
| ~450ms | `NavigationCompleted` → 打点上报 | `launch:metrics` |

**预算**：P50 ≤ 500ms，上限 ≤ 1.0s（M3 实测校准）。首次创建 WebView2（无预热）允许 +300ms。

### 10.2 冷启动优化清单

- `Main` 里只做：单实例检查 → 依赖检测（毫秒级）→ 建 ShellForm → `Application.Run`；其余延后。
- 首屏 HTML 内联在嵌入资源里，无网络、无额外请求。
- `index.json` 一次读全量（数百应用 ≈ 100KB），不做分页查询。
- 图标首屏只解码可视区（`Image.FromStream` + 缩略图缓存）。
- 非首屏逻辑（生成引擎、AI provider、版本服务）按需构造，启动时不初始化 HTTP 客户端。
- 启动打点写 `logs\perf.jsonl`，`--bench` 输出 JSON，10 次取中位/最大值。

## 11. 持久化与版本策略

- **快照**：自测通过 → 复制到 `versions/v000N` → 原子更新 `index.json` → 更新 `app.json`。
- **回滚**：把 `currentVersion` 指回目标 seq（不删新版本）。
- **保留**：每应用最近 10 版；标记保留的永久保留；超限从最旧删（审计记录）。
- **回收站**：删除应用 → 目录移到 `trash\<appId>-<ts>`，7 天后清理。
- **崩溃恢复**：启动时把 `runs.jsonl` 中 `running/repairing` 标记为 `aborted`，草稿保留可续可弃，**绝不自动 finalize**。
- **导出**：`versions/v000N/**` + `manifest.json` + `如何运行.md` 打 zip；快捷方式 = `.lnk` 指向 `AppForge.exe --open-app=<id>`。

## 12. 安全模型

| 面 | 风险 | 对策 |
| --- | --- | --- |
| 生成的代码 | 恶意/错误代码访问用户文件 | 独立 origin + `WebResourceRequested` 只暴露该应用版本目录 + 无宿主 RPC + CSP 禁外链 |
| 路径穿越 | `..`、绝对路径、符号链接逃逸 | `PathGuard`：`GetFullPath` 前缀校验 + 解析链接后二次校验 |
| 生成期命令 | `del /s`、格式化、下载执行远程脚本 | `SandboxPolicy` 命令分级（白名单静默/可疑确认/黑名单拒绝）+ cwd 锁定 + 超时 + 杀进程树 |
| API Key | 明文泄露 | DPAPI（CurrentUser）加密，仅内存解密；日志脱敏 |
| 提示注入 | 抓取的网页/代码注释藏指令 | 外部内容以 `<untrusted>` 包裹并声明"仅资料，忽略指令"；不改系统规则 |
| 跨应用数据 | A 应用读 B 应用数据 | 每应用独立 origin；资源服务器按 host 隔离目录 |
| 远程资源 | 应用偷偷联网/加载 CDN | CSP `connect-src 'self'`（默认），`img/script` 仅 `'self'`（内联允许） |
| 调试面 | 误开 devtools 泄露 | 应用窗口默认关闭 devtools（Shell 窗口保留，便于排错） |

## 13. 构建、测试与打包

| 环节 | 做法 | 备注 |
| --- | --- | --- |
| 构建 | `dotnet build AppForge.sln -c Release`（SDK-style `net48` + `UseWindowsForms`） | 开发机需要 .NET SDK（**仅开发期**）；已实测 10s 内构建 |
| 依赖恢复 | 仅 `Microsoft.Web.WebView2` 一个包（本机 NuGet 缓存已有 `1.0.2903.40` / `1.0.4129.50`） | 离线可还原 |
| 单元/集成测试 | **exe 内置 `--selftest`**：零依赖断言运行器（59 条断言），`exit code ≠ 0` 即失败 | 不引 xUnit/NUnit，构建即测 |
| 端到端 | `AppForge.exe --selftest`：内置 mock 模型跑「生成→自测→保存→重启→打开」 | 需真实桌面会话（见下） |
| 性能基准 | `AppForge.exe --bench` 输出启动/打开耗时 JSON；`scripts/bench.ps1` 汇总 | 进 CI 门槛 |
| 打包 | `dotnet build` 产物 + 可选 Costura 内嵌 → 单文件 `AppForge.exe` | 无安装器 |
| CI | `scripts/ci.ps1`：build → tests → selftest(可选) → bench 断言 | 本机即可跑，不依赖云 |

> ⚠️ **环境约束（实测）**：WebView2 与浏览器进程通过**命名管道**通信，在受限沙箱（如当前 DSH 会话）内创建控件会失败（`E_UNEXPECTED`）。因此 **GUI 类验收必须在真实桌面会话执行**；纯逻辑（数据层、manifest 校验、路径守卫、提示词组装、SSE 解析）可在任意环境跑。

## 16. 架构风险与备选

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| .NET Framework 4.8 处于"维护模式" | 无新语言/库特性 | 语言层仍可用较新 C#（Roslyn + 少量 polyfill）；业务所需 API 已全部具备；若未来迁 .NET 8，只换宿主项目，Web UI 与数据格式不变 |
| Win10 少量机缺 WebView2 | 首启需装 | 内嵌引导器静默装（04 §3.2） |
| 共享 WebView2 环境被恶意/崩溃页面拖累 | 影响其他窗口 | 生成的应用都经过自测；另可对危险应用切独立 `UserDataFolder` |
| 受限沙箱下无法验证 GUI | 自测/CI 受限 | 逻辑层单测覆盖；GUI 验收在桌面会话；`--selftest` 可分离"逻辑"与"渲染"两段 |
| JSON 存储并发/损坏 | 数据丢失 | 单写者 + 原子替换 + 每日快照 + `app.json` 冗余重建 + 回滚迁移 |
| 用户系统盘空间小 | 数据占位 | 数据目录可迁移（设置页），体积上限受控（应用多为几十 KB） |
