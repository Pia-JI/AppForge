# 04 · 依赖预算与首启自动安装

- 版本：v0.1
- 关联：[01 需求](01-需求规格说明书.md) · [02 架构](02-架构设计.md) · [03 任务规划](03-任务规划与里程碑.md)
- 本文回答一个问题：**这个软件到底需要用户装多少东西？**

---

## 1. 结论先说

> **v1 承诺：用户只需要一个 exe（或一个文件夹），双击就能用，安装型外部依赖为零。**
> 唯一例外是 WebView2 运行时——它在 Windows 11 上是操作系统自带的，Windows 10 上绝大多数机器已随 Edge 预装；**万一缺失，软件首次打开时会自己静默装好**，用户只需点一次"继续"。

| 项目 | 数值 |
| --- | --- |
| 安装型第三方依赖 | **0 个** |
| 第三方代码库（随包内嵌，无需安装） | 3 个 dll，合计 ≈ 0.8MB（WebView2 托管桥） |
| 交付体积 | 单 exe **≤ 5MB**（内嵌资源与桥 dll）；绿色目录版 ≤ 6MB |
| 首次启动需要联网的概率 | Windows 11：**0%**；Windows 10：仅当 WebView2 缺失时才需要（少数机型） |
| 需要管理员权限 | **否**（WebView2 缺失时按用户级静默安装） |

| # | 组件 | 作用 | 来源 | 需用户安装？ | 体积 |
| --- | --- | --- | --- | --- | --- |
| 1 | Windows 10 22H2+ / Windows 11 x64 | 操作系统 | — | — | — |
| 2 | **.NET Framework 4.8** | 宿主运行时（C# 执行环境） | **Windows 内置**（Win10 1903 起随系统提供，Win11 内置） | 否 | 0 |

| 5 | WebView2 SDK 托管桥（Core / WinForms / Loader） | 让 C# 调用上面那个运行时 | 随包内嵌（不需要 WebView2 SDK 另装） | 否 | ≈0.8MB |

## 3. 依赖自检与首启自动安装流程

### 3.1 启动检查顺序（毫秒级，不阻塞首屏）

```
AppForge.exe 启动
  ├─ 1. OS 版本检查         Win10 22H2(19045)+ / Win11      → 不满足：提示系统要求，退出
  ├─ 2. .NET Framework 4.8  Release ≥ 528040（读注册表）     → 不满足：提示并给官方链接，退出
  ├─ 3. WebView2 运行时       GetAvailableBrowserVersionString() → null 则表示缺失
  │      ├─ 有 → 继续（耗时 ~1ms）
  │      └─ 无 → 进入「依赖安装引导页」
  ├─ 4. 数据目录可写检查       %LOCALAPPDATA%\AppForge 写测试
  └─ 5. 首启额外自检          渲染一张自检页 + 存读一条数据 → 通过后标记 firstRunDone
```

第 2、3 步都在 `Application.Run` 之前完成（无窗口，纯检测），因此正常机器**没有任何额外启动开销**。

### 3.2 WebView2 缺失时的安装引导（唯一需要"装东西"的场景）

1. 显示一个原生 WinForms 小窗口（此刻还没有 WebView2 可用，必须用原生窗口）：
   > 「本软件需要 Microsoft Edge WebView2 运行库，它是 Windows 自带的网页组件。当前系统缺少它，需要安装一次（约 100MB，无需管理员权限）。」
2. 两条路径：
   - **在线静默安装（默认）**：运行随包内嵌的 `MicrosoftEdgeWebview2Setup.exe /silent /install`（引导器仅 ≈2MB，官方推荐方式，自动匹配架构、按用户安装）。进度条 + 日志。
   - **离线安装**：提供"选择离线安装包"按钮，支持用户自备官方 Evergreen 独立安装包（`MicrosoftEdgeWebView2RuntimeInstallerX64.exe`），同样 `/silent /install`。
3. 安装完成后**自动重启宿主**（`Process.Start(exe)` 后退出），重新走 §3.1 检查。
4. 失败兜底：显示官方下载页链接、错误码、日志路径，并提供"以纯原生模式启动"的降级选项（仅能管理文件、不能渲染 UI——用于让用户至少能导出/备份数据）。

> 为什么不像 Electron 那样自带内核？自带 = 每次更新都要重新分发 100MB+，且与系统已有 Edge 重复占空间；用系统运行时是"用 Windows 自带的组件"，正是本项目的诉求。

### 3.3 可选组件按需安装（v2 预留，v1 不触发）

| 可选组件 | 触发时机 | 安装方式 | 落位 |
| --- | --- | --- | --- |
| Python 3（用于生成脚本类工具） | 用户首次创建"脚本类应用" | 官方安装包静默装（用户级） | `%LOCALAPPDATA%\AppForge\runtimes\python` |
| Node.js（用于需要构建的前端框架应用） | 用户首次选择"框架应用" | 官方 zip 解压（免安装，便携） | `%LOCALAPPDATA%\AppForge\runtimes\node` |
| 构建工具（Vite 等） | 同上 | 走 Node 自带的包管理器，缓存到 `runtimes\npm-cache` | 同上 |

统一由 `DependencyRegistry` 管理：每项有 `检测()` / `安装()` / `版本` / `状态`，UI 里有一页"组件状态"可查、可修复、可卸载。v1 只注册前两项检测（WebView2、.NET Framework 4.8），列表为空也不报错。

## 4. 分发与卸载

| 形态 | 说明 | 优点 |
| --- | --- | --- |
| **单文件 exe（默认）** | `AppForge.exe`（内嵌 Shell UI 静态资源 + 3 个桥 dll） | 一个文件，拷走即用，无安装器、无注册表污染 |
| 绿色目录版 | `AppForge.exe` + `wwwroot\` + 3 个 dll | 便于换 UI、便于排错 |
| （不提供）MSI/NSIS 安装器 | — | 无需安装即可用，安装器反而增加负担 |

- 数据位置：默认 `%LOCALAPPDATA%\AppForge`；若 exe 同目录存在 `portable.flag`，则用 `.\data`（U 盘/便携场景）。
- 卸载：程序内"更多 → 清理数据"或直接删目录。卸载不残留进程、不写注册表（开机自启除外，会显式告知并可一键关闭）。
- 升级：替换 exe 即可，数据目录独立，向后兼容由迁移脚本保证。

## 5. 已做的验证（不是纸面推算）

本机（Windows 11 x64）实测：

| 验证项 | 结果 |
| --- | --- |
| .NET Framework 4.8 存在 | ✅ 已内置（系统组件） |
| WebView2 运行时存在 | ✅ 已内置 Evergreen 运行时（与 Edge 同源） |
| `GetAvailableBrowserVersionString()` 返回版本 | ✅ 成功返回，可作为首启检测手段 |
| net48 + WinForms + WebView2 工程构建 | ✅ `dotnet build` 10 秒成功（离线，NuGet 缓存还原） |
| 产物体积 | ✅ exe 9KB + Core.dll 590KB + WinForms.dll 38KB + Loader.dll 162KB ≈ **1.0MB** |
| WebView2 控件实际创建 | ⚠️ 在 DSH 沙箱内失败（`E_UNEXPECTED`）：WebView2 与浏览器进程走命名管道，沙箱禁止 → **GUI 验收须在真实桌面会话运行** |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Win10 少量机器缺 WebView2 | 首启需装 | 内嵌 2MB 引导器静默装（§3.2）；打不开时给官方链接 + 降级模式 |
| 企业环境禁止安装运行时 | 无法启动 | 提供"离线安装包"导入；文档给出 IT 部署指引（可走 WSUS/组策略） |
| 用户系统过旧（Win10 <22H2） | 不支持 | 首启明确提示最低版本；不静默升级系统 |
| `winsqlite3.dll` 属系统未公开 API | v2 若采用有兼容风险 | v1 用 JSON 存储；SQLite 仅作升级路径，并在接口层隔离 |
| 内嵌 dll 被安全软件误报 | 启动被拦 | 尽量少内嵌、不混淆、不打包下载器；提供绿色目录版备选 |
